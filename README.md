# 부산 문화 알림 (BusanCultureAlert)

컴퓨터에 로그인하면 부산의 전시·무료 공연·축제 정보를 모아서 디스코드 채널로 보내 줍니다.
하루에 한 번만 동작하고, 이미 보낸 항목은 다시 보내지 않으며, 기간 한정 전시는 종료 7일 전에 한 번 더 알려 줍니다.
Node.js만 있으면 되고 추가 패키지 설치는 필요 없습니다.

---

## 1. 필요한 키와 신청 링크

### (A) 공공데이터포털 인증키 — 필수, 키 1개로 아래 전부 사용
공공데이터포털에 가입하면 **개인 인증키 1개**가 나옵니다. 그 키로 아래 API마다 **"활용신청" 버튼만 눌러 두면** 됩니다 (개발계정은 자동승인, 반영까지 최대 1시간 정도 걸릴 수 있음).

| 우선순위 | API | 링크 | 용도 |
|---|---|---|---|
| 필수 | 부산광역시_전시 상세 서비스 | https://www.data.go.kr/data/15063738/openapi.do | 부산 전시 + **가격 텍스트** |
| 필수 | 부산광역시_문화 기타장르 목록 서비스 | https://www.data.go.kr/data/15063748/openapi.do | 공연·행사 + **유/무료 구분** |
| 권장 | 부산광역시_문화가 있는 날 목록 서비스 | https://www.data.go.kr/data/15063759/openapi.do | 매달 마지막 수요일 혜택 |
| 권장 | 한국문화정보원_한눈에보는문화정보조회서비스 | https://www.data.go.kr/data/15138937/openapi.do | 전국 공연·전시 중 부산 전시 (보완용) |
| 권장 | 한국관광공사_국문 관광정보 서비스 (TourAPI, KorService2) | https://www.data.go.kr/tcs/dss/selectDataSetList.do?keyword=국문%20관광정보%20서비스 | 부산 축제·행사 |

> 키는 마이페이지 → 데이터활용 → 인증키 발급현황에서 **"일반 인증키(Decoding)"** 값을 복사하세요. Encoding 키(%가 들어간 것)를 넣어도 자동으로 변환합니다.

### (B) KOPIS 인증키 — 선택
연극·콘서트 같은 공연을 더 촘촘히 받고 싶을 때만. 공공데이터포털과 **별도 키**입니다.
- https://www.kopis.or.kr/por/cs/openapi/openApiInfo.do?menuId=MNU_00074

### (C) 디스코드 웹훅 URL — 필수
알림 받을 채널 → 채널 편집(톱니바퀴) → 연동 → 웹후크 → 새 웹후크 → **웹후크 URL 복사**.

## 2. 설치 순서

1. 이 폴더를 원하는 위치에 둡니다 (예: `D:\Tools\busan-culture-alert`). 설치 후에는 폴더를 옮기지 마세요. 옮겼다면 3번을 다시 실행하면 됩니다.
2. `config.example.json` 을 복사해서 **`config.json`** 으로 이름을 바꾸고 키 3개를 넣습니다.
   - `dataGoKrKey`: 공공데이터포털 키
   - `kopisKey`: 비워 두면 KOPIS는 자동으로 건너뜀
   - `discordWebhookUrl`: 디스코드 웹훅 URL
3. 폴더에서 **`test-webhook.cmd`** 더블클릭 → 디스코드에 테스트 메시지가 오면 웹훅 OK.
4. **`check.cmd`** 더블클릭 → API별로 ✅/⚠️/❌ 점검 결과가 나옵니다 (`logs\check-날짜.txt` 에도 저장). 원본 응답까지 보려면 `node src\index.mjs --check --dump` → `logs\raw\`
5. **`dry-run.cmd`** 로 실제로 어떤 항목이 걸러지는지 미리 봅니다 (디스코드 전송 안 함).
6. PowerShell에서 자동 실행 등록:
   ```powershell
   cd "폴더경로"
   powershell -ExecutionPolicy Bypass -File .\install-task.ps1
   ```
   - 로그인 1분 뒤 창 없이 실행됩니다. 작업 스케줄러 등록이 막히면 자동으로 "시작프로그램" 바로가기로 대신 등록합니다.
   - 컴퓨터를 며칠씩 켜 두는 편이면 `-DailyAt "18:00"` 을 붙이면 매일 18시에도 확인합니다 (하루 1회 제한은 그대로).
   - 해제: `powershell -ExecutionPolicy Bypass -File .\uninstall-task.ps1`

## 3. 설정값 (config.json)

| 키 | 기본값 | 설명 |
|---|---|---|
| `maxPrice` | 20000 | 성인(일반) 기준 이 금액 이하만 |
| `includeUnknownPrice` | true | 가격 정보가 아예 없는 항목(축제 등)도 보낼지 — 보낼 때는 "확인 필요"로 표시 |
| `includePaidUnknownPrice` | false | "유료"인 건 알지만 금액을 모르는 공연도 보낼지 (켜면 알림이 많아짐) |
| `endingSoonDays` | 7 | 종료 며칠 전에 ⏰ 마감 임박 알림을 한 번 더 보낼지 |
| `lookaheadDays` | 30 | 앞으로 며칠 안에 시작하는 것까지 볼지 |
| `maxItemsPerRun` | 0 | 한 번에 보내는 최대 개수. `0` = 제한 없음 (숫자를 넣으면 넘는 건 다음 실행 때 이어서) |
| `openCalendarOnLogon` | true | 로그인할 때 캘린더 창도 자동으로 열지 |
| `kobisKey` | "" | 영화진흥위원회(KOBIS) 오픈API 키 — 영화 개봉 일정 (없으면 건너뜀) |
| `holidays` | true | 공휴일 표시 (공공데이터포털 '한국천문연구원_특일 정보' 활용신청 필요) |
| `popupRegions` | ["부산"] | 팝업스토어 자동 수집에서 남길 지역 (주소·제목 기준) |
| `popupMaxFetchPerRun` | 80 | 팝업 사이트별로 한 번에 새로 읽을 페이지 수 (서버 부담 줄이기) |
| `popupDelayMs` | 1000 | 팝업 페이지 사이 대기 시간 |
| `popupSites` | [] | 팝업 사이트 추가: `{ "id", "label", "open", "sitemap", "detail"(정규식) }` |
| `runOncePerDay` | true | 하루에 한 번만 동작 (재부팅해도 중복 알림 없음) |
| `cultureInfoRealms` | ["전시"] | 한눈에보는문화정보에서 받을 분야. `[]` 이면 전부 |
| `sources.*` | 전부 true | 소스별 켜기/끄기 |

카드 색: 🟩 무료 · 🟦 2만 원 이하 · ⬜ 가격 확인 필요 · 🟥 마감 임박

## 4. 캘린더 앱

조건을 통과한 **전체 행사**를 애플 캘린더처럼 위아래로 끝없이 스크롤되는 주간 격자 달력으로 보여줍니다. 세로 모니터에 맞춰 배치했습니다.

- 실행: 바탕화면 **Busan Culture Calendar** 아이콘(`install-task.ps1` 이 만듦) 또는 `calendar.cmd`. 로그인할 때도 자동으로 열림.
- 창: Edge 앱 모드(주소창 없는 독립 창). 세로 모니터로 옮겨 크기를 맞춰 두면 다음부터 그 자리에 열림.
- 막대 색: 🟧 축제 · 🟪 공연·행사 · 🟦 전시 · 🟩 문화가 있는 날. 빨간 `D-3` = 마감 임박, 빨간 점 = 최근 수집에서 새로 발견.
- 짧은 행사가 위쪽 줄을 먼저 차지하고, 3주 넘는 장기 행사는 뒤로 밀림. 줄이 모자라면 날짜 아래 `+N개 더`.
- 날짜 클릭 → 그날 행사 목록(이날 시작 / 마감 임박 / 진행 중), 막대 클릭 → 상세(상세 페이지·지도·검색 링크).
- 상단: 분류 필터, 무료만, 제목·장소 검색, `오늘`(단축키 T), 새로고침(전송 없이 API 다시 조회, 1~2분).
- 데이터: 알림 실행/`--dry-run`/새로고침 때마다 `data/events.json` 갱신. 지난 행사는 120일간 남겨서 과거로도 스크롤 가능. 창이 열려 있으면 30초마다 자동 반영.
- 창을 닫으면 몇 분 안에 로컬 서버(127.0.0.1:17863)도 스스로 종료.
- **즐겨찾기**: 카드의 ☆ 또는 상세의 '☆ 즐겨찾기' → 금색 막대 + ★, 해당 주에서 맨 위 줄. 상단 '★ 즐겨찾기만'으로 모아 보기. `data/favorites.json` 에 저장(행사가 목록에서 사라져도 유지).
- **관심 없음(숨기기)**: 카드의 ✕ 또는 상세의 '관심 없음' → 캘린더와 **디스코드 알림에서 모두 제외**. 바로 '되돌리기' 가능, 상태줄 '숨김 N개'에서 다시 보기. `data/hidden.json`.
- **직접 추가**: 상단 '+ 일정' 또는 날짜 목록의 '+ 이날 일정 추가' → 팝업스토어/내 일정(제목·기간·시간·장소·링크·메모). 상세에서 수정·삭제. `data/custom-events.json`.
- **☰ 전체 보기**: 오늘 이후 예정된 모든 항목을 시작일순 목록으로 보고 미리 거르기. 분류 탭(건수 표시)·검색·'★만'·'숨긴 항목 보기' 켜고 끄기, 줄마다 ☆/✕, 체크해서 **여러 개 한 번에** 즐겨찾기·숨기기·다시 보기.
- **영화는 캘린더에 기본으로 안 나옴** — 전체 보기의 '영화 개봉' 탭에서 ★ 누른 것만 캘린더에 표시.
- **영화 개봉**(청록, 성인물 포함) · **팝업스토어**(분홍) · **공휴일**(날짜 옆 빨간 글씨).
- 디스코드 알림: 기존 문화행사 + **팝업 수집 결과 전부**(팝가의 부산 공연·축제 포함) + **즐겨찾기한 영화**(즐겨찾기 후 첫 실행 때 1번, 개봉 전날·당일에 ⏰ 한 번 더). 즐겨찾기 안 한 영화와 공휴일은 캘린더에만.
- **팝업 자동 수집**: 팝플리·팝가·데이포유 사이트맵 → 상세 페이지를 천천히 읽어 부산 주소만 남김(robots.txt 준수, 읽은 페이지는 `data/popup-cache.json` 에 저장해 다시 안 읽음). 막힌 사이트는 상태줄 '팝업 사이트 ⚠'에서 '사이트 열기'로 직접 확인 후 '+ 팝업 직접 추가'.

## 4-1. 클라우드 실행 (GitHub Actions, `mode: "cloud"`)

- 수집·디스코드 알림·7일 요약 Gist 갱신을 **GitHub Actions 가 30분마다** 실행 (`.github/workflows/collect.yml`, 매시 7분·37분). PC가 꺼져 있어도 동작.
- 밤 11시~아침 8시(`quietHours`)에는 수집·Gist 갱신은 계속하고 디스코드 알림만 모아 두었다가 아침 첫 실행 때 전송.
- 팝업 사이트는 3시간마다만 접속(`popupIntervalHours`), 그 사이엔 저장해 둔 결과 사용.
- 키·웹훅·토큰은 저장소 Secrets 의 `BCA_CONFIG`(config.json 내용 전체)에만 있음. 공개 저장소에는 코드만 올라감. 실행 기록에서는 키가 가려짐.
- PC와 클라우드는 비공개 **상태 Gist** 를 같이 씀: 클라우드는 수집 결과·보낸 기록·팝업 캐시를, PC 캘린더는 즐겨찾기·숨김·직접 추가를 올림(서로 상대 파일은 안 건드림).
- PC: 로그인 때 수집하지 않고 캘린더만 엶. 캘린더는 3분마다 클라우드 결과를 받아 오고, 새로고침 버튼은 클라우드 실행을 바로 요청(1~3분).
- 공개 저장소는 60일간 활동이 없으면 예약 실행이 꺼지므로 `keepalive.yml` 이 매달 1일 작은 커밋을 남김.
- 하루 호출량(30분마다): 부산 전시 약 1,440/10,000 · TourAPI 약 100/1,000 · KOBIS 약 150/3,000.

## 5. 7일 일정·즐겨찾기 API

오늘부터 7일 동안의 일정(날짜별 시작·마감, 공휴일)과 즐겨찾기 목록. 규칙은 캘린더와 같음(숨긴 항목 제외, 영화는 ★ 한 것만, 직접 추가 포함).

| 어디서 | 주소 |
|---|---|
| 이 PC (캘린더가 켜져 있을 때) | `http://127.0.0.1:17863/api/week` (JSON) · `/api/week?format=text` (한국어 요약) · `/api/week?days=14` · `/api/favorites/list` |
| 밖에서 (아이패드 단축어 등) | 비공개 GitHub Gist — `node src\index.mjs --publish` 가 출력하는 JSON·텍스트 주소 (고정) |

- Gist 는 알림 실행·새로고침·dry-run 때, 그리고 캘린더에서 즐겨찾기·숨기기·직접 추가를 바꾸면 몇 초 뒤 자동 갱신(내용이 같으면 안 올림). PC가 꺼져 있어도 마지막 내용을 읽을 수 있음. GitHub 캐시 때문에 반영까지 몇 분 걸릴 수 있음.
- 설정: GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token, 권한은 **gist** 하나만 → `config.json` 의 `githubToken`.
- 비공개(secret) Gist 는 검색에 안 나오지만 **주소를 아는 사람은 읽을 수 있음** → 주소 공유 금지.
- JSON 구조: `range{from,to,days}`, `counts`, `days[{date,weekday,holiday,starting[],ending[],ongoingCount}]`, `events[]`(기간 안 전체), `favorites[]`(끝나지 않은 즐겨찾기 전체). 항목: `title,type,start,end,time,place,info,price,url,source,favorite,startsInDays,endsInDays`.

## 6. 파일 구성

```
src/index.mjs     진입점 (--check / --dry-run / --force / --test-webhook / --refresh-events)
src/events.mjs    캘린더용 행사 스냅샷 (data/events.json)
src/digest.mjs    7일 일정·즐겨찾기 요약 (JSON/텍스트)
src/publish.mjs   요약을 비공개 GitHub Gist 로 올리기
src/sources.mjs   API별 수집기
src/core.mjs      필터 · 중복제거 · 신규/마감임박 판정
src/discord.mjs   디스코드 카드 생성 · 전송
src/http.mjs      호출 · 재시도 · 공공데이터포털 오류 해석
run.vbs           창 없이 실행하는 런처 (작업 스케줄러가 호출, 캘린더도 함께 엶)
calendar/         캘린더 앱 (server.mjs = 로컬 서버, public/ = 화면)
calendar.vbs      캘린더를 콘솔 창 없이 실행 (바탕화면 아이콘이 호출)
calendar.cmd      캘린더 수동 실행
data/             캘린더 데이터 (자동 생성)
state.json        이미 보낸 항목 기록 (자동 생성, 지우면 처음부터 다시 알림)
logs/             실행 로그
```
